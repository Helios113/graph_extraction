# Series 3 findings: Hugging Face transformers

> Earlier CPU-EP run, kept as a record: `JacobianExtractorLoss` (then called `MaskedSumLoss`) was still optimised here. The current GPU run and its findings are in [../series3/FINDINGS.md](../series3/FINDINGS.md).

See [test_plan.md](../../test_plan.md). Code: `tests/series3/run_series3.py`, configs in `tests/series3/configs/` (generated by `construct/make_config.py`), run on ngog CPU (CPU EP, no TF32) via `tests/series3/run.sh`. Input: random token ids, batch 2, sequence 8. Baseline: torch hooks / autograd on the HF model itself (boundary values and logits for the forward checks; gradients through an injected layer input).

Boundaries: h0 = embeddings, h(2l+1) = post-attention of layer l, h(2l+2) = post-MLP. Spans checked per model: h0->h1, h1->h2 (single sublayers), h0->h2 (one layer), h2->h4, last layer, h0->h6 (three layers). Pullbacks for all four loss types on every span; mid-layer spans are forward-only for the torch gradient comparison (no injectable torch boundary), the layer-aligned ones are compared against torch autograd. The 30-step SGD / AdamW trajectory is run on the multi-layer span.

Criteria: static checks (extraction, loss, gradient) < 1e-4 (deep fp32; series 1 used 1e-5), trajectories < 1e-3.

## Conclusion

- **Forward, extraction, pullback loss and gradient pass** the static criteria for all five models, all 4 loss types and all spans (largest: 1.7e-5 gradient on qwen2.5-0.5b, 1.5e-5 extraction on opt-125m). Full-model ORT logits match torch to <= 3e-4 absolute on logits of size 15–105.
- **Optimisation**: 36 of the 40 model x loss x optimiser trajectories agree to <= 2.2e-4, AdamW agrees to <= 2.8e-6 and every adversarial loss with SGD to <= 2.2e-4. **Four trajectories exceed the 1e-3 criterion, all `JacobianExtractorLoss` with SGD** (tinystories 6.6e-2, gpt2 2.8e-3, smollm2 2.0e-3, opt 1.2e-3). 

## Findings and caveats

- **The four trajectory misses are an unbounded-objective effect, not a gradient error.** JacobianExtractor is a linear objective; SGD with lr 0.01 for 30 steps drives it from O(1–1e3) to -2e5 / -9e4 / -4e3 / -57 (gpt2 / smollm2 / opt / tinystories) with no stationary point, so fp32 gradient differences of 1e-6 (which pass the static check) are amplified step by step. The same models with AdamW (normalised steps) agree to <= 2.8e-6, and with the adversarial losses (which have a minimum) to <= 2.2e-4. This is the likely explanation, but was not isolated by rerunning in float64.
- **No transformer with control flow was tested.** The plan asks for models "with and without control flow"; all five exported graphs contain no `If`/`Loop`/`Scan` (`control_flow: false` in every `results.json`), so only the without-control-flow half is covered. Given series 2 (If/Loop break extraction and pullback), a transformer export that does contain them would be the next test.
- **Export path**: models are exported with the project's own `construct.model_export` (`torch.onnx.export`) through `ensure_base_model`, not through `optimum`. The KV-cache series (4, 5) does use optimum.
- Only the mid-layer spans h0->h1 and h1->h2 lack a torch gradient comparison (forward and pullback construction only); all layer-aligned spans, including h0->h6, are compared against torch autograd.
- CPU EP only; the GPU/TF32 behaviour is covered in series 4 and 5.
